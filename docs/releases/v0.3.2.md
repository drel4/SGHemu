# SGHemu v0.3.2

## Changes

- Faster CPU data reads/writes through checked RAM/ROM page fast paths.
- Bounded execution batches avoid redundant peripheral dispatch while preserving
  instruction execution, device deadlines, MMIO side effects and IRQ/FIQ timing.
  **No idle-loop skipping, overclocking or JIT.**
- The supplied GUI is an optimized **MSVC 2026 x86 Release + PGO** build. Source
  includes an optional instrument/train/optimize workflow; ordinary Release
  builds include the RAM/batching improvements without requiring training data.
- Fixed speed-meter jumps caused by pairing stale guest snapshots with current
  wall timestamps. The display now uses a rolling two-second progress average;
  genuine sustained slowdowns remain visible.
- LCD presentation and ghosting can refresh independently of the CPU/audio
  mutex. Brief partial redraws are filtered, with bounded capture for continuously
  drawing content so games cannot starve display updates.

## Verification and performance

The full Release regression suite passed, including CPU differential, memory,
peripheral, network/WAP, audio and import tests. New coverage includes 40,019
data-bus checks, 573,929 batch-versus-step checks and presentation/speed-meter
regressions. Native charger tests passed on XEDA2/XEDD1/XEDK1, and XEDK1 WAP
fetch/reopening worked with Yamaha audio active. Startup/ringtone-selection PCM
was byte-identical between single-step and batched execution.

Three alternating silent XEDK1 benchmark rounds measured median throughput of
17.534 Msteps/s before versus 32.923 Msteps/s with data/batching fast paths
(about 1.9x). Separately trained benchmark PGO reached 40.514 Msteps/s; that is
not a claim of the same additional gain in the GUI. Live audio remains paced
at real time. See [measurements and constraints](https://github.com/drel4/SGHemu/blob/v0.3.2/docs/bounded-execution.md).

## Running and compatibility

Extract the entire archive and launch **`build/sghemu-gui.exe`**. Keep the supplied
layout. Supply your own firmware pair and `M5_EmuHw.dll` for Yamaha audio.
The optimized GUI needs no compiler/PGO runtime DLLs.

**C100XEDK1 remains best tested.** XEDA2/XEDD1 retain experimental compatibility;
Java/media importing is not equally verified across versions. Other SGH models
are not supported yet. This remains a pre-release.

No firmware, Yamaha DLLs, media, NVM/SIM snapshots, personal settings or PGO
training databases are included. Project code/binaries use the WTFPL; third-party
notices remain separate. Windows 7 targeting is retained; execution there is untested.
